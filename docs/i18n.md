# Internationalization (i18n)

LinPlayer ships with English (`en`) and Persian (`fa`) UI translations.

## Architecture

- Library: [`i18next`](https://www.i18next.com/) + [`react-i18next`](https://react.i18next.com/).
- Translation files: `src/renderer/src/i18n/locales/{en,fa}/common.json` — a
  single `common` namespace, organized by feature area (`nav`, `settings`,
  `player`, `empty`, `toast`, …).
- Initialization: `src/renderer/src/i18n/index.ts`, imported once from
  `main.tsx` before the app renders.
- No UI string is hard-coded in a component — every piece of user-facing
  text goes through `useTranslation()` / `t('key')`.

## Adding a string

1. Add the key to `locales/en/common.json`.
2. Add the same key, translated naturally (not machine-translated), to
   `locales/fa/common.json`.
3. `tests/unit/i18n.test.ts` asserts both files define exactly the same set
   of keys and that no value is empty — CI fails if a translation is
   missing, which is the "validation strategy for translation keys"
   referenced in the milestone spec.

## Fallback behavior

`fallbackLng: 'en'` — a missing key in the active language falls back to
English rather than rendering blank/undefined. In development,
`missingKeyHandler` logs a console warning so missing keys are caught
early instead of silently shipping.

## Language switching

The active language lives in `AppSettings.appearance.language` (persisted
to SQLite like every other setting). `App.tsx` is the single source of
truth that reacts to it: it calls `i18n.changeLanguage()` and
`setDocumentLanguage()` (which sets `<html lang>` and `<html dir>`)
whenever the setting changes — no full app restart required.

## RTL

Persian renders with `dir="rtl"` on `<html>`. Rather than mirroring the
whole UI with a blanket CSS transform (which the milestone spec explicitly
warns against — "do not simply mirror the entire application blindly"),
layout uses CSS **logical properties** throughout
(`ps-*`/`pe-*`, `ms-*`/`me-*`, `border-s`/`border-e`, `start-*`/`end-*`,
`text-start`/`text-end`) instead of physical left/right utilities. These
map to `padding-inline-start`, `margin-inline-end`, etc., which the
browser itself flips based on `direction` — so most components need no
RTL-specific code at all; flexbox and CSS grid also reorder their main
axis automatically under `dir="rtl"`.

**Deliberate exception — playback transport controls.** The player
transport row (play/pause/skip, progress bar, elapsed/remaining time) is
wrapped in an explicit `dir="ltr"` container. This matches the convention
used by most media players (Spotify, YouTube Music, VLC) even in RTL
locales: playback position and transport direction read left-to-right
universally, and mirroring them would be confusing rather than helpful.
This is a conscious exception, not an oversight — logical properties are
still used everywhere else, including the settings, sidebar, playlists,
search, dialogs, and context menus.

## Persian typography — Shabnam

The `Shabnam` font (`Shabnam.ttf`, supplied in the project root by the
maintainer — its license was not verified as part of this change and
should be confirmed before public release) is bundled via `@font-face` in
`src/renderer/src/styles/globals.css`, referencing the file at
`src/renderer/src/assets/fonts/Shabnam.ttf`. Vite's CSS asset pipeline
hashes and copies it into the build output automatically (verified in
`out/renderer/assets/Shabnam-*.ttf` and inside the packaged
`app.asar`), so no manual packaging step is required.

`:root[lang='fa']` sets `--app-font: 'Shabnam', Tahoma, ui-sans-serif, sans-serif`,
and `body` always reads `font-family: var(--app-font)` — so the whole app
switches typeface the moment the language changes, with no per-component
overrides needed.
